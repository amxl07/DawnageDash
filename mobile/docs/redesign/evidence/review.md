## Strengths

- Durable outbox replacement precedes remote writes. Serialized storage mutations run separately from network delivery; exact revision checks protect newer content from older acknowledgments. Permission/conflict failures remain distinct from retryable connectivity failures, with sanitized persisted error metadata.
- Check-in presentation shares one model/controller across the single-scroll and rollback wizard. The original sixteen-field payload and validation are retained. Numeric staging is synchronous, typed values are committed before submit, invalid text stays editable, Copy/Undo reconciles focused text, and date/exit intents preserve the originating reporting scope.
- Workout entry resolves account/date/log identity and asynchronous dependencies explicitly. Owned explicit IDs cannot fall through into an arbitrary date record; retained legacy text is protected from replacement with empty structured data. Current-set controls, incomplete-set review, and opt-in rest behavior preserve the existing coaching policies and V2/legacy wire format.
- Profile recovery uses an account-scoped journal and confirms returned users/assessment rows before advancing or clearing recovery. The code merges owned patches into freshly read JSON, preserves unknown keys and unrelated assessment answers, and distinguishes a completed Profile update from pending assessment synchronization.
- Home no longer invents hardcoded activity targets or conflates reported observations with completed workouts. Its section-level error/stale states, dated observations, explicit recovery routes, and canonical full-profile query avoid several prior sources of misleading state.
- The tests include deferred asynchronous boundaries and real controller/numeric-control interactions, not only static snapshots. The delivery tests inspect retained payloads and revision behavior; Profile tests cover unusable positive acknowledgments; the reminder tests address native-operation/read ordering.

### Important

**A — P2, corrected at f0e0370: An intervening blocked explicit workout prevents the selected mixed-group continuation from ever retrying.**

The correction now walks retained explicit predecessors in order under their own IDs before sending the selected null version. The new real-wrapper regression observes A success, B transport failure, durable B/null retention, then B/A resumption and an empty queue. The original primitive deadlock is closed; see C for the introduced controller consequence of returning B after failure.

- **Source at `a220ad8`:** `mobile/src/lib/outbox.ts:102-119`; `mobile/src/features/workout/useWorkoutSession.ts:102-105`.
- **Trigger:** Retain a same-date group in order `[blocked explicit A, blocked explicit B, later null]`, with A and B owned and available. Select A in deliberate recovery. The new code durably sets the null item's `retryLogId` to A, then successfully retries/removes explicit A.
- **Consequence:** It immediately attempts the null item, but the exact retry guard rejects it because B is now first. On refresh, the selected association restricts recovery targets to A. The remaining predecessor is B, and line 103 requires that predecessor's own ID equal selected target A; each further attempt rejects. B is permanently blocked and cannot clear through automatic flush. All bytes remain durable, but the recovery action cannot progress. This is a residual case of finding 4, not an external release gate or a completed recovery implementation.
- **Correction:** Keep the null item's explicit chosen destination while processing each intervening retained explicit predecessor against that predecessor's immutable own ID and in original order. Preserve exact revision checks, positive delivery receipts and ordinary conflicting-save rejection.
- **Required regression:** Exercise the exact A/B/null sequence with A successful and B initially blocked, then retry B and reach the retained null destination. Include interruption/transport failure between predecessors and continuation, reload from storage, and assertions that B is never redirected to A and no retained payload is dropped or replayed out of order.

**B — P2, corrected at f0e0370: A partial draft association cannot be retried because its own destination is treated as a new conflict.**

The draft-only branch now reaches the helper before the queued-association destination precheck. The helper retains its exact-content comparison and storage/generation guards. Its real in-memory storage regression fails source deletion once, verifies both copies, retries successfully, and verifies source removal plus preserved selected content. The separate controller regression verifies this helper is reached despite an existing destination. These are complementary layer tests, not a single mounted-controller test with real draft storage.

- **Source at `a220ad8`:** `mobile/src/features/workout/useWorkoutSession.ts:337-350`; `mobile/src/hooks/useWorkoutDraft.ts:195-219`.
- **Trigger:** Select owned A for a null-ID draft with no outbox. The new destination-first helper writes A's draft, then `AsyncStorage.removeItem(sourceKey)` at line 209 fails transiently. Its catch returns false, leaving both acknowledged copies intact. The controller stays on selection and tells the user to retry.
- **Consequence:** Retrying reaches the unconditional existing-destination rejection at controller line 339 before `associateDraft` can execute its matching-destination continuation at hook lines 195-200. The original recovery cannot finish after storage recovers. Opening A manually does not retire the unscoped source, so the stale source remains discoverable. This retry trap is introduced by the finding-3 correction; preserving bytes alone does not close the required recovery path.
- **Correction:** Allow the draft-only helper to recognize and finish its own identical destination-first attempt, while continuing to refuse unrelated destination drafts. An alternative is a safely owned rollback of the new destination when source cleanup fails. Preserve source and identity/generation guards.
- **Required regression:** Use the controller and real draft-storage behavior: destination write succeeds, first source deletion rejects, retry succeeds once storage recovers, navigation opens the exact preserved A payload, and the unscoped source is removed. An unrelated occupied destination must remain unchanged and refused.

**C — P2, corrected at 8267ea6: An intervening failure moves newer draft content to the failed predecessor's ID.**

The wrapper now separates an intermediate delivery receipt from an actionable edited-content destination. A failed predecessor returns no navigation/draft destination; selection metadata and original source aliases keep the existing route resumable. During deliberate recovery, intermediate identity events cannot attach the draft independently. Completion attaches a null draft only to its selected destination and retains the current ID of an already-explicit draft. The real wrapper/controller/QueryClient/draft-storage harness covers A/B/null and A/null/B, newer protected drafts, unchanged unrelated draft bytes, null and explicit entry routes, remount and successful resumption.

- **Changed source:** `mobile/src/lib/outbox.ts:114-116`; interacting with `mobile/src/features/workout/useWorkoutSession.ts:280-290` and `mobile/src/hooks/useWorkoutDraft.ts:132-137`.
- **Trigger:** Open the null-ID outbox item in the same `[explicit A, explicit B, later null]` recovery, with a newer retained null-ID draft. Choose A. The controller restores and flushes that newer draft. A succeeds, then B fails. The new loop returns B as `result.logId`, accurately identifying the failed delivery but not the destination selected for the draft.
- **Consequence:** `complete()` treats `result.logId` as the edited content's destination and executes `attachPersistedWorkoutId(..., B)` followed by `flushDraft()`. The newer draft is now written under B, and the original null-ID source is removed. An existing B draft can also be overwritten: only the selected A destination was checked before recovery. The chosen null outbox association remains A while the newer local draft has moved to B. The wrapper test's correct B receipt assertion does not exercise this controller boundary.
- **Correction:** Separate the failed predecessor's receipt/navigation state from the selected destination and current draft identity. An intermediate failure must preserve newer draft content under its originating or deliberately selected identity, without overwriting another explicit draft or hiding the remaining recovery.
- **Required regression:** Mount the controller for the null retained item with a newer draft; choose A; deliver A then fail B. Verify B's status remains actionable, the null association remains A, the newer draft never becomes B, any existing B draft is unchanged, and retry can finish B then the selected null version before saving the newer edits to A. Exercise real draft-storage behavior at this boundary or an equivalently faithful integration harness.
